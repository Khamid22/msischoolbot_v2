# Project Rules And Editing Guide

This is the safe map for learning and changing the MSI School project.

## One-Sentence Architecture

PostgreSQL stores the truth, `shared/db` reads and writes it, `web/backend`
controls permissions and APIs, `web/frontend` displays the app, and `tgbot`
handles Telegram only.

## Protected Rule

Never delete database values.

Database cleanup means:

- normalize inconsistent values
- fill missing canonical fields
- add safer query/write paths
- preview affected rows before changes
- keep the change reversible

Database cleanup does not mean:

- deleting rows
- truncating tables
- dropping columns
- overwriting many values without a preview

## Folder Map

```text
shared/
  academics/        subject/date/school canonical rules
  identity/         account login, passwords, Telegram links, profiles
  db/               PostgreSQL connection, tables, shared SQL queries

tgbot/
  handlers/         Telegram command/callback handlers
  keyboards/        Telegram inline keyboard builders
  helpers.py        bot formatting/helper functions

web/backend/
  server.py         Flask app composition
  routes/           small system-level routes
  auth/             web auth/session helpers
  roles/            role-specific backend workflows
  domains/          reusable backend business domains
  utils/            web-only utility helpers
  static/react/     generated React build output

web/frontend/src/
  app/              React app bootstrap and page map
  shared/           reusable frontend UI and browser helpers
  roles/            role-specific React screens
```

## Backend Roles

Role folders answer: "What does this user type do?"

```text
web/backend/roles/admin/
web/backend/roles/student/
web/backend/roles/parent/
web/backend/roles/teacher/
web/backend/roles/ceo/
web/backend/roles/customer_support/
web/backend/roles/owner/
```

Put user-facing workflows here. Examples:

- parent child snapshot
- student dashboard payload
- admin upload flow
- teacher class view
- CEO revenue overview
- customer support complaint queue

## Backend Domains

Domain folders answer: "What school business area is this?"

```text
web/backend/domains/identity/
web/backend/domains/academics/
web/backend/domains/payments/
web/backend/domains/resources/
web/backend/domains/announcements/
web/backend/domains/complaints/
web/backend/domains/people/
web/backend/domains/communication/
```

Put reusable web-backend business logic here. Example: payments can be used by
admin, CEO, parent, and support, so payment logic belongs in a domain unless a
piece is truly role-specific.

## Frontend Roles

React source should stay under:

```text
web/frontend/src/app/
web/frontend/src/shared/
web/frontend/src/roles/
```

Use:

- `roles/student/pages/` for student screens
- `roles/parent/pages/` for parent screens
- `roles/admin/pages/` for admin screens
- `roles/admin/panels/` for admin panel tabs
- `shared/ui/` for reusable components
- `shared/lib/` for frontend-only helpers

Do not bring back these old folders:

```text
web/frontend/src/pages/
web/frontend/src/components/
web/frontend/src/lib/
web/frontend/src/hooks/
```

## Generated Files

Do not manually edit:

```text
web/backend/static/react/
```

That folder is generated by:

```bash
cd web/frontend
npm run build
```

## Import Rules

Allowed:

```text
tgbot -> shared
web/backend -> shared
web/frontend -> web/backend through HTTP/API only
shared -> shared/db
```

Forbidden:

```text
tgbot -> web/backend
web/backend -> tgbot
shared -> web/backend
shared -> tgbot
web/frontend -> Python modules
```

## Where To Edit

| Change | Edit |
|---|---|
| Subject names, short names, date cleanup | `shared/academics/` |
| Login, password, account linking | `shared/identity/` |
| SQL query | `shared/db/queries/` or `shared/db/cross_queries/` |
| Table/schema helper | `shared/db/tables.py` |
| Telegram bot text/buttons | `tgbot/handlers/`, `tgbot/keyboards/` |
| Student backend page/API | `web/backend/roles/student/` |
| Parent backend page/API | `web/backend/roles/parent/` |
| Admin backend page/API | `web/backend/roles/admin/` |
| Reusable backend payments/resources/etc. | `web/backend/domains/<domain>/` |
| Student React screen | `web/frontend/src/roles/student/pages/` |
| Parent React screen | `web/frontend/src/roles/parent/pages/` |
| Admin React screen/panel | `web/frontend/src/roles/admin/` |
| Shared React component | `web/frontend/src/shared/ui/` |

## What To Avoid

- Do not make one giant refactor together with a feature.
- Do not rename database concepts casually.
- Do not add compatibility shims unless there is a real migration reason.
- Do not copy a service into another folder. Move ownership or import the owner.
- Do not manually edit built React chunks.
- Do not fix frontend by changing database values.
- Do not fix backend by hardcoding frontend-only assumptions.

## Naming Rules

Use `docs/GLOSSARY.md`.

The most important names:

```text
student_code       login code, for example MSI00001
student_row_id     database row id from students.id
```

## Safe Feature Workflow

Use this mini-template before adding a feature:

```text
Feature:
Role:
Domain:
Data needed:
Existing query or new query:
Backend endpoint/page:
Frontend screen or Telegram message:
Verification command:
```

Example:

```text
Feature: Parent sees child attendance lessons
Role: parent
Domain: academics
Data needed: child enrollment_id, lesson_date, attendance status
Existing query or new query: shared/db/queries/parent_queries.py
Backend endpoint/page: web/backend/roles/parent/routes.py
Frontend screen: web/frontend/src/roles/parent/pages/ParentHome.tsx
Verification: compileall, frontend typecheck/build
```

## Debug Ladder

When something is missing or broken, check in this order:

1. Is the value in PostgreSQL?
2. Does the `shared/db` query return it?
3. Does the backend service receive it?
4. Does the route/API/bootstrap payload include it?
5. Does React or the bot render it?

This prevents random edits.

## Verification Commands

Backend:

```bash
python3 -m compileall -q shared tgbot web/backend scripts main.py
python3 - <<'PY'
from web.backend.server import app
print(app.name)
PY
```

Frontend:

```bash
cd web/frontend
npm run check-types
npm run build
```

Import boundary checks:

```bash
rg "from tgbot|import tgbot" web/backend shared
rg "from web.backend|import web.backend" tgbot shared
rg "@/pages|@/components|@/lib|@/hooks|src/pages|src/components" web/frontend/src
```

Duplicate scans:

```bash
find shared web/backend tgbot scripts -name '*.py' -type f -print0 \
  | xargs -0 shasum | sort \
  | awk 'seen[$1]{print prev[$1]"\n"$0"\n"} {seen[$1]=1; prev[$1]=$0}'

find web/frontend/src -type f \( -name '*.ts' -o -name '*.tsx' \) -print0 \
  | xargs -0 shasum | sort \
  | awk 'seen[$1]{print prev[$1]"\n"$0"\n"} {seen[$1]=1; prev[$1]=$0}'
```
